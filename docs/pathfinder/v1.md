# Pathfinder v1 API (`pathfinder.v1.PathfinderService`)

> **v1 is the legacy API surface.** It is kept unchanged for existing consumers and identifies chains only via a single `sender_address`/`receiver_address` pair on `FindPathRequest`; any intermediate broker/PFM chain address is derived automatically via SLIP-44-guarded bech32 re-encoding. **New integrations should use [v2beta](./v2beta.md) instead**, which replaces that derivation with explicit, caller-supplied per-chain addresses. See [`overview.md`](./overview.md) for the protocol/transport details shared by both versions and the accepted denom syntax.

List of all methods on `pathfinder.v1.PathfinderService`:

- `FindPath`
- `LookupDenom`
- `GetTokenDenoms`
- `GetChainInfo`
- `ListSupportedChains`
- `GetChainTokens`

A machine-readable OpenAPI 3.1 spec for this service is generated at [`../openapi/v1.openapi.yaml`](../openapi/v1.openapi.yaml) (`make generate-openapi`).

## FindPath

The `FindPath` query is used to find the best route to bridge tokens between two chains. It will return the best route to the designated chain.

### FindPath - Request

The request should contain the following fields:

- `chain_from`: The chain ID of the source chain.
- `token_from_denom`: The denom of the token on the source chain.
- `amount_in`: The amount of the token to bridge.
- `chain_to`: The chain ID of the destination chain.
- `token_to_denom`: The denom of the token on the destination chain.
- `sender_address`: The address of the sender.
- `receiver_address`: The address of the receiver.
- `smart_route`: Whether to return a smart route or a normal route (optional, default is false).
- `slippage_bps`: The slippage in basis points (optional and only applicable if the swap is required, default is 100).

See [Denom syntax](./overview.md#denom-syntax) for the accepted forms of `token_from_denom`/`token_to_denom`.

### FindPath - Response

`FindPathResponse` has a `route` field that is one of `direct`, `indirect`, or `broker_swap` - exactly one is populated depending on the route shape the Pathfinder found. Below is a worked JSON example for each shape.

#### Direct Route

This is a simple IBC transfer route between the two chains. It will return a single route to the destination chain. Example:

```json
{
  "success": true,
  "error_message": "",
  "direct": {
    "transfer": {
      "from_chain": "osmosis-1",
      "to_chain": "atomone-1",
      "channel": "channel-94814",
      "port": "transfer",
      "token": {
        "chain_denom": "ibc/BC26A7A805ECD6822719472BCB7842A48EF09DF206182F8F259B2593EB5D23FB",
        "base_denom": "uatone",
        "origin_chain": "atomone-1",
        "is_native": false
      },
      "amount": "100000"

```

For this to occur we first need to send the ATOM to the Osmosis broker chain - this is done by sending an IBC transfer to Osmosis. This is the data required to execute the transaction using the Skip smart contracts. If something really goes wrong with the smart contract you might need to contact Skip, since they operate the contract. #### Multi-hop Route

It is a bit rare, but it might happen that some chains route through other chains for intermediate hops (to my knowledge, only Sei does this via Osmosis for some tokens). Another reason this shape might show up: sending a token that has usage on chain A and chain B, but instead of making 2 separate transactions we use Packet Forwarding Middleware (PFM). Example:

  "error_message": "",

## GetChainInfo

This method is used to get information about a chain. It returns the chain ID, chain name, and basic information about the chain, including which other chains it has routes to and what tokens are allowed on each route.

### GetChainInfo - Request

The request should contain the following fields:

- `chain_id`: The chain ID of the chain.
- `show_symbols`: Whether to show the symbols of the tokens on the chain (optional, default is false).

## GetTokenDenoms

This method is used to get denom information for a token across chains.

### GetTokenDenoms - Request

The request should contain the following fields:

- `base_denom`: The base denom of the token.
- `origin_chain`: The chain ID of the chain where the token is native.
- `on_chain_id`: The chain ID to filter results to (optional, default is to return the denoms across all Pathfinder-supported chains).

## LookupDenom

This method is used to resolve denom information for a single token on a single chain.

### LookupDenom - Request

The request should contain the following fields:

- `chain_id`: The chain ID of the chain to resolve the denom on.
